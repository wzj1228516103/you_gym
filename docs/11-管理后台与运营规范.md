# YOU GYM 管理后台与运营规范

版本：1.0  
更新日期：2026-08-14  
技术栈：Vue 管理后台 + Spring Boot Admin API

## 1. 后台目标

后台用于管理解剖节点、动作、计划、饮食覆盖、媒体、资源包、通知、审核和系统配置。它不是简单 CRUD：任何会影响动作安全、肌肉映射或用户计划的变更都必须经过版本、审核、预览和发布流程。

## 2. 角色权限

| 角色 | 主要权限 | 禁止事项 |
| --- | --- | --- |
| 超级管理员 | 账号、权限、系统配置、紧急回滚 | 不默认参与专业审核 |
| 内容编辑 | 编辑动作、文案、媒体元数据 | 不能独立发布 L2/L3 内容 |
| 专业审核人 | 审核动作、安全、计划与肌肉映射 | 不能修改系统权限 |
| 3D 资源管理员 | 模型节点、对象 key、资源清单、预览 | 不能审核训练处方 |
| 营养内容管理员 | 食品覆盖、自定义食谱、营养文案 | 不能改供应商原始值 |
| 运营人员 | 推荐位、通知草稿、反馈分流 | 不能查看完整敏感健康数据 |
| 客服 | 用户工单、脱敏账号状态 | 不能导出批量健康数据 |
| 审计员 | 只读审计日志和发布记录 | 不能写入业务数据 |

高风险发布、批量下线、资源 manifest 上线和权限修改需要二次确认；L3 动作至少两名不同审核人批准。

## 3. 全局后台布局

- 左侧固定导航，折叠后仅保留图标和 Tooltip。
- 顶部包含环境标识、全局搜索、待审数量、通知和账号。
- 内容区使用 12 列栅格，列表筛选区不放入卡片，表格和编辑面板单层呈现。
- 生产环境顶部显示醒目的“生产”标签；危险操作使用 `color-error`，不使用移动端荧光主色表达危险。
- 所有页面显示面包屑、资源 ID、版本和保存状态。

管理后台可沿用 `design.md` 的颜色语义，但信息密度、表格和操作布局按桌面效率设计，不照搬移动端底部导航。

## 5. 仪表盘

只展示可行动信息：待专业审核、媒体失败、资源下载失败率、FatSecret 错误率、短信异常、用户高风险反馈、待发布版本。禁止把 DAU 等指标堆成无行动意义的卡片墙。

每个异常卡有负责人、最近发生时间、影响范围和跳转入口。图表必须支持时间范围和数据点详情。

## 6. 动作库

### 6.1 列表

列：动作 ID、名称、模式、主要肌肉、器械、难度、风险等级、审核状态、发布版本、更新时间、负责人。筛选支持以上字段、缺失媒体、缺失降阶动作和收到风险反馈。

批量操作只允许：分配负责人、加标签、导出审核清单、暂停低风险内容。批量发布和批量修改肌肉映射默认禁用。

### 6.2 编辑器

采用分段页面：基础信息、分类、肌肉映射、教学步骤、训练参数、错误与安全、进阶/降阶、媒体、版本记录。右侧持续显示完成度和阻断项；自动保存草稿，但提交审核前要求显式确认。

教学步骤支持排序，不允许富文本产生任意颜色和字号。安全提示使用结构化字段。参数编辑按目标/等级建立覆盖矩阵。

### 6.3 动作预览

提供 390 × 844 客户端预览，可切换 iOS/Android、加载/错误/无媒体状态和中文长文本。预览不等于发布，必须显示当前草稿版本水印。

## 7. 解剖中心

### 7.1 解剖树

左侧树展示区域 → 肌群 → 肌肉 → 肌束/分部 → 展示结构。右侧编辑名称、层级、左右侧、是否可训练、模型对象 key、镜头预设和说明。

移动节点前显示受影响的动作映射、深链和模型资源。已发布稳定 ID 不允许修改，只能新增替代节点并建立迁移关系。

### 7.2 3D 预览

后台嵌入 Unity WebGL 或专用预览工具，支持男女模型、表/深层、左右侧、对象边界、点击命中、聚焦镜头和高亮材质。审核人可在同屏比较节点元数据与视觉结果。

### 7.3 动作映射

为每个可训练节点设置主要/次要/稳定动作、参与度、依据、审核状态。系统阻止把肌腱、韧带、起止点作为训练目标，也阻止无审核依据的批量映射发布。

## 8. 训练计划后台

### 8.1 计划编辑器

填写目标、人群、经验、场地、器械、周期和周频率；用周/日结构编辑热身、主训练和拉伸。动作行支持组数、次数、休息、RPE、节奏、替代组和说明。

实时校验：

- 周频率与日程数量一致。
- 必需器械与计划标签一致。
- 每个训练日有热身和安全说明。
- L3 动作满足先决条件和审核要求。
- 同一肌群恢复间隔异常时给出提示，不自动阻止专业人员调整。

### 8.2 版本和用户影响

发布新版本前显示正在使用旧版的用户数和变更差异。默认仅新加入用户使用新版；若存在安全修复，可通过迁移策略通知现有用户并保留历史快照。

## 9. 饮食后台

- 查看 FatSecret 调用状态、缓存命中和字段完整度，不展示/修改供应商密钥。
- 食品覆盖层可编辑中文别名、分类、常用份量展示和审核备注，不能悄悄改写供应商原始营养值。
- 营养目标公式、安全下限和提示文案采用版本化配置，需要营养专业审核。
- 用户自定义食品默认不可见；只有处理具体工单且具备权限时才能临时查看脱敏内容。

## 10. 媒体与资源管理

### 10.1 上传流程

上传 → 格式/病毒检查 → 元数据提取 → 转码 → 缩略图 → 人工质检 → 绑定内容 → 发布。状态包括 UPLOADING、PROCESSING、REVIEW、READY、FAILED、ARCHIVED。

### 10.2 3D 资源包

显示包名、性别、层级、版本、依赖、大小、哈希、最低 App 版本、灰度比例和错误率。发布前必须完成测试设备矩阵、哈希校验、断点续传和回滚包验证。

## 11. 审核工作流

审核单包含资源类型、版本、修改摘要、风险等级、提交人、审核角色、检查清单、评论和附件。审核人只能批准自己未提交的高风险变更。

结论：通过、退回修改、暂停内容、需要第二审核、需要外部专业意见。退回必须选择原因并给出可执行评论；重新提交保留上一轮记录。

## 12. 发布与回滚

内容发布使用不可变 release：包含动作版本、计划版本、解剖数据版本、媒体清单和最低客户端版本。发布顺序为 staging 验证 → 内部用户 → 5% → 25% → 100%。

回滚不删除新版本，而是把当前指针切换到已验证版本。安全紧急下线可立即暂停单个动作/计划，不必等待整个 release 回滚。

## 13. 通知与短信后台

- 普通训练和饮食通知仅能选择 Push/In-App，界面中不提供 SMS 选项。
- SMS 模板仅归属验证码、账号安全、重要系统三类，模板 ID 和签名在白名单配置。
- 发送前显示预计目标数、渠道、文案、深链和敏感字段检查。
- 重要批量通知需要双人批准、灰度和撤回/停止能力。
- 短信日志显示脱敏手机号、模板、请求 ID、结果和供应商错误映射，不展示验证码。

## 14. 用户反馈与客服

反馈按动作安全、内容错误、3D 映射、训练记录、饮食数据、账号和其他分类。高风险词或 L3 内容自动提高优先级，但只作为分流，不能自动判定伤病。

客服只能查看处理所需最小数据；查看敏感记录需填写理由并写入审计。禁止后台直接修改用户训练历史，纠错通过版本化补丁并保留原始值。

## 15. 审计与安全

记录登录、导出、查看敏感数据、角色变更、内容编辑、审核、发布、回滚、通知发送和系统配置。审计日志只追加，不允许普通管理员删除。

后台强制 MFA、闲置超时、异常登录提醒和最小权限。导出使用异步任务、短期签名链接和水印；大批量导出需高级审批。

## 16. Figma 后台关键页面

首轮至少设计：登录/MFA、仪表盘、动作列表、动作编辑、动作对比审核、解剖树 + 3D 预览、动作映射、计划编辑、媒体处理、审核队列、发布详情、通知编辑、用户反馈、角色权限和审计日志。

每个页面必须包括加载、空、错误、无权限、保存中、未保存、版本冲突和成功反馈状态。

## 17. 验收标准

- 权限矩阵可阻止越权查看、编辑、审核和发布。
- 已发布稳定 ID 不可被直接修改或删除。
- 高风险内容不能由提交人单独批准。
- 计划、解剖、动作和资源均可版本化发布与回滚。
- 普通提醒配置页没有 SMS 渠道，短信日志不暴露验证码。
