# YOU GYM 埋点、测试、验收与发布

版本：1.0  
更新日期：2026-08-14

## 1. 质量目标

首版必须证明四个核心闭环可用：从肌肉到动作、从计划到完成训练、从食品到当天营养汇总、从注册到个性化设置。质量评价优先关注任务完成、数据可靠、内容安全和恢复能力，不只看页面是否符合静态稿。

## 2. 埋点原则

- 只收集改进产品所需数据，使用匿名 `analyticsUserId`。
- 禁止上传手机号、验证码、自由文本备注、具体体重/体脂、完整食品搜索词和动作反馈中的健康描述。
- 事件名使用 `snake_case`，属性有 schema 和版本。
- 页面曝光只在可见超过 500ms 后上报，避免预加载重复计数。
- 离线事件本地排队，限制容量和保留期；用户退出或撤回分析授权后清理。

## 3. 事件公共字段

`eventId`、`eventName`、`eventVersion`、`occurredAt`、`sessionId`、`analyticsUserId`、`platform`、`appVersion`、`buildNumber`、`locale`、`timezone`、`networkType`、`screenId`、`experimentIds`。

3D 性能事件可带设备性能档位、模型包版本和 FPS 档，不上传精确设备指纹。

## 5. 指标定义

### 5.1 激活

- 注册完成率 = `auth_sms_verified(success)` / `auth_phone_submitted(valid)`。
- 首次设置完成率 = `onboarding_completed` / 首次登录用户。
- 首次价值完成率 = 24 小时内完成肌肉聚焦、查看动作详情或开始训练的用户 / 新用户。

### 5.2 核心闭环

- 肌肉到动作转化 = 查看动作详情人数 / 完成肌肉聚焦人数。
- 计划开始率 = 开始首次训练人数 / 加入计划人数。
- 训练完成率 = COMPLETED/ENDED_EARLY 会话 / 已开始会话，需分别展示正常与提前结束。
- 饮食记录完成 = 一天记录至少两餐人数 / 打开饮食页人数；不把三餐作为唯一健康标准。

### 5.3 稳定性

- Unity 首帧成功率、肌肉选择失败率、资源下载成功率。
- 训练会话恢复成功率、离线同步成功率、重复记录率。
- API P95/P99、崩溃自由用户、ANR、FatSecret 可用率和短信成功率。

## 7. 设备与系统矩阵

### 7.1 iOS

- 当前主版本和前一个主版本。
- 小屏设备、标准设备、大屏设备。
- 低电量模式、动态字体、深色模式（产品固定暗色但系统控件需兼容）、通知拒绝和有限存储。

### 7.2 Android

- 覆盖目标最低 API、主流 API 和最新 API。
- 低/中/高三档 GPU 与内存。
- 全面屏、挖孔屏、三键导航和手势导航。
- 厂商后台限制、通知渠道关闭、存储不足和网络切换。

主设计画板 390 × 844，必须额外检查 360 × 800；文本放大 200% 时关键任务仍可完成。

## 8. 核心 E2E 场景

1. 新用户手机号登录，验证码成功，完成目标/经验/场地设置，看到推荐依据。
2. 打开人体页，切换女性模型，在下拉导航选择“肩部 → 三角肌 → 前束”，镜头聚焦、高亮，进入动作筛选。
3. 无高精度包时下载资源，中断后续传；存储不足时可清理并重试。
4. 筛选家庭 + 哑铃动作，查看步骤/错误/安全，加入临时训练。
5. 加入三分化计划，开始训练，完成组、修改重量、休息计时、替换动作、提前退出再恢复，最终完成同步。
6. 无网完成训练，杀进程重启，记录恢复且联网后不重复上传。
7. 搜索 FatSecret 食品、切换份量、记录午餐、编辑和删除，汇总和历史快照正确。
8. 拒绝通知权限后训练计时仍运行，个人页能引导到系统设置。
9. 后台编辑动作、专业审核、灰度发布、客户端看到新版本；回滚后恢复旧版。
10. 用户导出数据、申请删除并在撤回期取消。

## 9. 3D 专项测试

- 模型男女切换、左右节点、表层/深层、透明层和展示结构。
- 点击命中精度：目标可见区域内的误选率；细小节点提供下拉/快速定位补充。
- 镜头插值无穿模、无眩晕式旋转，聚焦后肌肉不被浮层遮挡。
- 高亮只作用于目标节点，次级肌肉语义一致；退出选择能正确还原材质。
- 资源版本不匹配、哈希失败、CDN 超时、断点续传、低内存卸载和 Unity 初始化失败。
- 30 分钟持续操作检查内存增长、温升、掉帧和系统杀后台恢复。

## 10. 安全与隐私测试

- 短信接口频控、重放、验证码暴力尝试和账号枚举。
- access/refresh token 轮换、设备吊销、越权读取 `/me` 数据。
- 管理后台 RBAC、MFA、导出审批、审计不可删除。
- 上传伪装文件、超大文件、恶意元数据和签名 URL 过期。
- 分析事件扫描，确保无手机号、验证码、自由备注和具体健康值。
- 删除账号后 token、push token、个人媒体和业务数据按策略失效。

## 11. 可访问性验收

- 所有可点击区至少 44 × 44px。
- VoiceOver/TalkBack 能朗读按钮名称、状态、进度和图表摘要。
- 颜色不作为唯一状态信息，肌肉高亮同时有名称、轮廓和路径。
- “减少动态效果”开启后，600ms 镜头动画缩短为淡入/直接定位，不闪烁。
- 训练中主要操作可单手完成，数字输入支持正确键盘和单位说明。

## 12. 内容验收

- 动作结构化字段完整，AI 初稿有人工审核记录。
- 所有可训练肌肉至少有 3 个审核动作，且主要/次要角色合理。
- 每套计划有热身、主训练、拉伸、替代动作和风险提示。
- L2/L3 内容符合审核人数和 UI 风险提示。
- 媒体无肢体/器械错误、版权不明、关节裁切或错误方向。

## 13. 发布门槛

发布候选必须满足：

- P0/P1 测试通过，P2 有明确接受人和修复版本。
- 核心 E2E 在 iOS/Android 真机通过。
- 崩溃、ANR、API、Unity 首帧、资源下载和同步指标达到阈值。
- 内容抽检和专业审核完成。
- 隐私政策、短信模板、FatSecret 授权和商店素材完成。
- 数据迁移、资源 manifest 和回滚演练通过。

## 14. 灰度与监控

内部 → 1% → 5% → 25% → 100%。每一阶段至少观察崩溃自由率、Unity 初始化、训练保存、登录、资源下载、食品搜索和严重反馈。指标异常时暂停扩量；客户端二进制回滚困难时使用功能开关关闭问题模块或回退资源版本。

## 15. 上线后响应

P0：数据丢失、认证不可用、严重安全/内容风险，立即停止发布并启用回滚/下线。P1：核心流程大面积失败，2 小时内确定缓解措施。每次事故完成时间线、根因、用户影响、修复、长期措施和验证记录。

## 16. 最终验收清单

- [ ] 四个一级模块和所有 P0 页面均有正常/加载/空/错/离线状态。
- [ ] 男性与女性 3D 基础模型可用，高精度资源可独立下载。
- [ ] 肌肉选择到动作筛选全链路可完成。
- [ ] 训练计时、组记录、进程恢复和离线同步可靠。
- [ ] FatSecret 食品搜索、份量和历史快照正确。
- [ ] 阿里云短信只用于验证码与重要通知。
- [ ] 管理后台审核、发布、灰度和回滚可用。
- [ ] 分析、日志和告警不包含敏感明文。
