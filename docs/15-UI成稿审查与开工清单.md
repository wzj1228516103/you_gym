## 1. 结论

当前 UI 成稿足够开始 Phase 1 的客户端开发，不需要等待 Figma、Unity 或所有生产凭证。

成稿已经覆盖最重要的正常态路径：

`人体选择 → 解剖层级 → 动作筛选 → 动作详情 → 加入训练`

以及训练计划、训练执行、休息计时、饮食搜索、个人首页和提醒设置的主要视觉方向。视觉上已经形成明确基线：纯黑背景、深灰表面、荧光黄绿主操作色、洋红肌肉高亮、冷灰蓝正反面人体模型。

当前不建议直接宣称“生产就绪”。成稿主要是正常态展示，认证、首次设置、异常恢复、离线、权限、资源下载和历史趋势仍需要补充状态画板。这些不阻塞 Phase 1，但必须在 P0 验收前完成。

## 3. 可直接采用的默认决策

以下默认值不会改变当前产品方向，可以直接进入 Phase 1；若产品负责人没有反对，按此实现：

| 事项 | Phase 1 默认值 | 原因 |
| --- | --- | --- |
| 认证 | 仅手机号 + 阿里云验证码 | 已在 PRD 定义，第三方登录另行评估 |
| 游客 | 未登录可浏览人体和动作详情；保存计划、训练记录、饮食记录时要求登录 | 保证核心体验可试用，同时保护用户数据 |
| 自定义计划 | 支持基础自定义：新增、删除、排序动作和覆盖组次/次数/休息 | 计划编辑已在 P0 页面清单中 |
| 第三方登录 | 首版不做 Apple/微信登录 | 减少认证和合规变量 |
| 健康平台 | 首版不接 Apple Health / Health Connect | 不影响训练记录闭环 |
| 食物识别 | 首版不做条码扫描和拍照识别；保留接口扩展位 | 先验证 FatSecret 搜索和手动记录 |
| 主题 | 首版仅深色 Fitness Neon V2，不提供主题切换 | 当前成稿和 `design.md` 已明确深色视觉 |
| 动效 | 默认 450–600ms 画布缩放和位移；遵循系统 Reduce Motion，关闭时使用淡入/直接定位 | 兼顾定位感和可访问性 |
| 人体节点 | 先按 `docs/04-3D人体模块专项.md` 的首版目录建立 2D 热区；可训练节点由专业审核冻结，展示节点不进入动作筛选 | 避免把无限细节误导为孤立训练能力 |
| 媒体 | 原型使用占位或已授权自有媒体；GitHub 数据集图片/GIF 暂不进入生产 | 仓库声明 Gym visual 媒体不受 MIT 覆盖 |

## 4. 开工前必须补齐的外部输入

这些事项不阻塞静态 UI、Mock API 和本地交互，但会阻塞生产联调或上架：

1. FatSecret 中国区商业授权、套餐、应用凭证和允许缓存字段。
2. 动作媒体授权或自有媒体方案。未取得 Gym visual 独立许可前，不能把仓库中的图片/GIF 上传到生产对象存储。
3. 阿里云短信签名、模板、地域、频控策略和生产凭证。短信只允许验证码、账号安全和重要通知。
4. Push 供应商及证书：iOS APNs、Android FCM 或目标市场合规第三方。
5. 服务端部署信息：域名、MySQL、Redis、对象存储/CDN、密钥管理和环境划分。
6. 动作内容专业审核人，以及涉及疼痛、受伤、孕期、慢性病内容的审核边界。

## 5. 建议的 Phase 1 实施边界

第一阶段先完成一个可演示、可测试、无外部商业依赖的闭环：

1. React Native 四 Tab 外壳和深色设计 token。
2. 人体模块的正式 2D 人体画布、正反面、男性/女性切换、区域下拉、四级路径、热区高亮和聚焦动画。
3. 动作筛选页：目标肌肉、场地、器械、难度、无结果和加载状态。
4. 动作详情页：步骤、常见错误、安全提示、参数和媒体占位。
5. 加入临时训练，并进入训练前概要；记录先存本地 Mock 数据。
6. 版本化人体节点数据、2D 热区映射和素材缺失时的文字导航降级入口。

FatSecret、短信、Push 和对象存储在接口稳定后接入，不把供应商密钥放入客户端或仓库。

## 6. 交付验收门槛

Phase 1 具备以下条件即可继续真实后端联调：

- 390×844 和 360×800 无重叠、无裁切，底部四 Tab 可用。
- 点击区域、路径或肌肉后，选中节点、路径和动作筛选条件同步更新。
- 聚焦动画在 750ms 内完成；连续点击只保留最后一次请求。
- 动作筛选支持加载、无结果、错误和离线占位。
- 动作详情在无媒体时仍可阅读步骤和安全提示。
- 临时训练可以创建、返回和恢复；网络不可用时不丢失本地记录。
- 2D 人体素材缺失或热区映射失败时，文字导航和动作筛选仍可用。
- 所有颜色、字号、圆角、间距和动效遵循 `design.md`。
