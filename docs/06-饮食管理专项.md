# YOU GYM 饮食管理专项

版本：1.0  
更新日期：2026-08-14  
适用范围：React Native 客户端、Spring Boot 服务端、Vue 管理后台、Figma 原型

## 1. 模块目标

饮食管理为训练计划提供可执行的能量与营养记录。首版只做“查找食物、按餐记录、查看当天目标和趋势”，不做医疗诊断、不把卡路里显示为对用户的惩罚，也不强制用户称重。所有营养建议均需带“估算/参考”标识。

一级入口为底部导航“饮食”。社区模块不进入首版一级导航。

## 2. 数据源与授权

### 2.1 主数据源

正式主数据源采用 FatSecret Platform API 中文区数据。上线前必须完成商业授权、调用套餐、中文食品覆盖和缓存政策确认；未完成授权时不得把接口数据作为生产内容公开发布。

服务端负责调用 FatSecret，客户端不直接持有供应商密钥。服务端保存供应商原始 `providerFoodId`、本地标准化字段、来源和同步时间。

### 2.2 标准营养字段

| 字段 | 单位 | 规则 |
| --- | --- | --- |
| `energyKcal` | kcal | 统一按可食用份量计算 |
| `proteinG` | g | 蛋白质 |
| `carbohydrateG` | g | 碳水 |
| `fatG` | g | 脂肪 |
| `fiberG` | g | 膳食纤维，可为空 |
| `sugarG` | g | 糖，可为空 |
| `sodiumMg` | mg | 钠，可为空 |
| `saturatedFatG` | g | 饱和脂肪，可为空 |
| `servingAmount` | decimal | 原始份量数值 |
| `servingUnit` | enum | 克、毫升、个、片、碗、份等 |

供应商缺失字段显示“暂无数据”，禁止前端补零后宣称为精确值。营养素值保留 1 位小数，热量取整显示。

### 2.3 本地标准化

服务端建立 `food_normalized` 表，将同一食物的中文名称、别名、品牌、分类和常用份量归一化。供应商数据不修改原始值；人工编辑只能写入覆盖层并保留审计记录。搜索结果必须显示来源标识：`FatSecret`、`YOU GYM 自定义` 或 `审核食谱`。

## 3. 用户目标与能量估算

### 3.1 首次设置字段

- 生理性别：男、女、不愿透露；仅用于能量估算，不在公共页面展示。
- 出生年份或年龄区间。
- 身高、体重、可选体脂率。
- 目标：减脂、维持、增肌、提升体能。
- 日常活动量：久坐、轻度、中度、高度。
- 每周训练频率和训练时长。
- 饮食偏好：不限、素食、乳糖不耐、用户自定义备注。

### 3.2 估算公式

默认使用 Mifflin-St Jeor 估算基础代谢率，再乘活动系数得到 TDEE。用户不提供性别或年龄时，使用保守区间并要求确认，不显示“精确代谢率”。

```text
男性 BMR = 10 × 体重(kg) + 6.25 × 身高(cm) - 5 × 年龄 + 5
女性 BMR = 10 × 体重(kg) + 6.25 × 身高(cm) - 5 × 年龄 - 161
TDEE = BMR × 活动系数
```

首版默认调整区间：减脂为 TDEE - 10%~20%，维持为 TDEE ±5%，增肌为 TDEE +5%~10%。任何结果都必须显示“估算值，非医疗建议”，用户可手动设定目标热量。低于产品安全下限时阻止保存并引导咨询专业人士，安全下限由后台配置且需审核。

### 3.3 宏量营养目标

宏量营养以区间呈现，不制造单一正确答案：

- 蛋白质：按目标体重或当前体重的配置区间计算，默认 1.2–2.0 g/kg；专业审核人可按目标和训练水平覆盖。
- 脂肪：默认占目标热量 20%–35%。
- 碳水：剩余热量折算，训练日和休息日可分别配置。
- 纤维：显示建议区间，不作为强制完成项。

UI 必须同时显示总热量、蛋白质、碳水、脂肪三个主进度，其他营养素放入“更多营养”。进度超过目标时使用中性提示，不使用红色警告，除非存在用户主动设置的安全阈值。

## 4. 餐次与记录模型

默认餐次：早餐、午餐、晚餐、加餐。用户可以重命名、隐藏或新增餐次，排序保存在个人设置。

每条记录包括：

- 食物 ID、来源、名称和品牌。
- 选中的份量数值、单位及换算后的克数/毫升数。
- 记录餐次、日期、时间和时区。
- 营养快照，保存当时数值，避免供应商后续更新导致历史变化。
- 可选备注、图片和“训练前/训练后”标签。
- `createdAt`、`updatedAt`、软删除标记和同步状态。

记录操作必须支持撤销 5 秒；删除历史数据前使用确认对话框。重复食物可从“最近记录”和“常用”快捷添加。

## 5. 页面与交互规格

### NUT-01 饮食首页

顶部显示日期切换和同步状态；第一视觉区为今日热量环与“三大营养素”横向进度。下方按餐次展示已记录食物和“添加食物”按钮，再下方为饮水、最近记录和目标说明。无记录时显示空状态和一个主 CTA，不放装饰性卡片堆叠。

### NUT-02 食物搜索

搜索框支持中文名称、品牌和别名；输入 2 个字符后开始请求，使用 300ms 防抖。筛选入口为餐次、食物类型、品牌、每份热量区间和“仅显示有完整营养数据”。最近搜索不包含敏感数据，用户可一键清空。

### NUT-03 搜索结果

列表行显示名称、品牌/来源、常用份量、热量及蛋白质；右侧为添加图标。结果分页 20 条，滚动到底自动加载并显示加载骨架。无结果时提供拼写建议、创建自定义食物入口和清除筛选操作。

### NUT-04 食物详情与份量

显示食物来源、份量步进器和单位下拉。调整份量时实时计算热量和宏量；小数份量需允许输入但按来源精度限制。底部固定“添加到餐次”按钮，点击后进入 NUT-05。

### NUT-05 记录确认

确认食物、份量、餐次、日期、训练标签和备注。保存成功以 Toast + 局部更新反馈，不强制离开当前上下文。

### NUT-06 餐次详情

显示餐次总热量、食物列表、编辑/删除和复制到其他日期。底部展示蛋白质、碳水、脂肪合计。餐次为空时提供“从最近记录添加”。

### NUT-07 自定义食物

用户可输入名称、份量单位、热量和营养素；必填名称、单位、热量。自定义食物必须标记为“个人数据”，不能被当作全局食品发布；支持编辑版本和删除。

### NUT-08 饮食历史

默认按周显示每日热量和蛋白质趋势，支持切换月视图、目标、餐次和体重关联。数据点不足 3 天时显示“继续记录后生成趋势”，不绘制误导性的虚线趋势。

## 6. 目标日程规则

- 目标按用户时区的自然日计算，跨午夜记录归入用户选择的日期。
- 训练日目标可与休息日不同；训练计划变更不回写已完成日期。
- 用户手动修改目标后标记为“自定义目标”，推荐计划不得悄悄覆盖。
- 目标变更需展示变更前后差异并允许取消。

## 7. 离线、同步与冲突

- 最近 30 天食品缓存和个人记录可离线查看；供应商搜索离线时返回本地缓存并显示“离线结果”。
- 新增/编辑/删除先写本地队列，网络恢复后按 `idempotencyKey` 上传。
- 同一餐次发生冲突时按记录 ID 合并；同一条记录两端都编辑时保留服务端版本并给用户“查看差异/保留本机”选择。
- 供应商食品下架后历史快照保留，新增时显示“暂不可用”。

## 8. 饮食安全与文案

- 页面固定说明：营养值来自公开数据库或用户输入，可能存在误差。
- 不根据单次超标推断健康风险，不使用“作弊餐”“罪恶”等羞辱性词语。
- 涉及过敏原时显示供应商提供的过敏原字段；未知时显示“请查看包装”。
- 快速减重、极低热量、疾病饮食需跳转安全提示，禁止直接给出治疗方案。

## 9. 验收标准

- 用户能在 30 秒内搜索并记录一项食物，份量变更后营养值正确更新。
- FatSecret 数据经服务端代理、缓存和来源标识后才返回客户端。
- 离线新增记录在恢复网络后只创建一次，失败可重试。
- 历史记录使用营养快照，不因供应商更新而改变。
- NUT-01 至 NUT-08 均包含加载、空、错误、离线和成功状态设计。
