# App 数据接入审计

检查日期：2026-08-19

## 已接入数据库

| 模块 | 数据来源 | 当前行为 |
| --- | --- | --- |
| 短信登录注册 | `app_user`、用户会话与短信服务 | 登录、注册、游客模式和会话恢复已接 API |
| 个人资料 | `app_user` | Onboarding 可录入身体数据、目标、经验、频率、场地和器械 |
| 人体肌群 | `anatomy_node` | App 从 `/api/v1/anatomy/tree` 读取，接口失败时保留本地人体热区兼容数据 |
| 动作目录 | `exercise_catalog`、`exercise_resource` | 动作筛选、详情、计划和快速训练读取数据库目录；媒体地址由 API 返回 |
| 训练计划 | `training_plan`、`training_plan_item` | 计划首页、计划库和详情读取 `/api/v1/plans`；开始计划会写入当前训练队列 |
| 训练记录 | `workout_record` | 按实际计时、组数、重量、次数、容量和热量保存；历史页读取用户记录 |
| 食物目录 | `food_catalog` | 搜索和详情读取 `/api/v1/foods` |
| 饮食记录 | `nutrition_record` | 按食物和克数计算营养后保存；饮食首页读取用户记录 |
| 内容资源 | `content_item` 及媒体资源表 | 动作详情读取已发布内容，图片、视频、GIF 和 3D 地址由内容 API 返回 |
| 埋点 | `analytics_event` | 人体、动作、训练、饮食和社区入口事件已进入统一埋点队列 |

## 本地兼容数据

人体热区与动作模块仍保留 `src/data/mockData.ts` 作为接口不可用时的离线兼容数据。正常连接 API 时，动作目录以数据库数据为准；人体树和动作目录已经拆成独立同步，单个接口失败不会拖累另一个接口。

当前训练队列只保存在 App 内存中。它由计划详情、快速训练或动作详情生成，不再用固定的前两个动作冒充“今日计划”。

## 本次清理

- 删除了未被导航使用、且固定保存鸡胸肉套餐的 `MealRecordScreen`。
- 移除了计划详情中的固定评分与虚构评价数量，单次时长改由数据库动作数量估算。
- 修复“结束训练”保存全零或固定汇总的问题，提前结束时也传递真实已完成组数。
- 快速训练和数据库计划现在都会把所选动作写入当前训练队列。
- 多动作训练会逐组累计实际容量，并按训练队列继续到下一动作。
- 休息页显示当前训练传入的组数、重量和次数，不再显示固定的 `80kg`。
- 通知、存储和营养目标页不再展示伪造数据，未接入能力统一显示真实空态。

## 接入优先级

下一阶段建议依次实现：用户当前计划与进度、收藏云同步、身体测量历史、提醒设置、通知中心、设备缓存统计。前三项会直接影响训练闭环和个人数据可信度。
